DAG 线程与其他线程的数据通信图谱

一条 SystemsThread（120Hz） 按拓扑序内联跑完 Mechanics → {Geometry, Acoustics} → Optics → Display；其余线程——主线程、CEF 编辑器 UI、脚本、网络——通过 7 类通道与它交换 54 个结构体、312 个字段。每条链路都标了方向、同步方式与源码位置。

01先看结论

DAG 线程不是“又一个 worker 池”：它是一条串行执行器。因此它与外部的通信只有两种形态—— 共享内存（谁先落锁谁生效）和控制面消息（队列/事件/收据）。 文档按这两类拆开，每个字段都标注了真实写者与读者。

  • 01
    字段级共享只有 C1。SharedDataHub 的 14 个 Storage 每槽一把 shared_timed_mutex，锁粒度是整个 Device：读一个字段也要锁整槽，因此“字段级并发”不存在，只有“槽级并发”。
  • 02
    CameraDevice 是唯一三方竞争的热点。主线程 API 创建、CEF 经命令队列更新、脚本线程 CameraFollowController 直写；三者之间没有序号或优先级仲裁。
  • 03
    帧图像闭环其实是同线程跨 tick。Optics 与 Display 都在 DAG 上，OpticsFrameReadyEvent 的回调就在 DAG 线程；收据（C6）解决的是 GPU 异步，不是线程竞争。
  • 04
    EventBus 是同步的，回调线程 = 发布线程。跨线程安全靠纪律：Acoustics 在回调里加锁入队，Display 只存图层不合成。没有机制强迫你这么做。
  • 05
    唯一“主线程等 DAG”的点是 surface 移除。DisplaySurfaceRemovedEvent.done 是 promise：DAG 在 tick 内拆完 swapchain 才兑现，主线程随后才销毁窗口。
