把 DAG 的内部数据收回来：外部线程读写面清单

DAG 线程内部有 179 个设备槽字段，其中 154 个仍被 DAG 之外的线程直接读写——123 个可被外部写、118 个被外部读、87 个双向。真正已经私有的只有 25 个。这份文档逐个列出这些字段、触碰它们的线程、访问路径，以及收回建议。

五个判断

  • 01
    最大入口不是队列，是 EngineAPI 门面。154 个边界字段里有 124 个被 EngineRuntimeAPI 直接碰过：它既创建槽位、又提供同步 getter/setter，调用方是 CEF 与脚本，等于把内部结构暴露成了公共 API。
  • 02
    87 个字段是双向的。外部既读又写（典型：CameraDevice、GeometryDevice），这类字段最难封——必须先定义“谁拥有”，再拆成命令 + 查询两条路。
  • 03
    CameraDevice 是单点最大泄漏面。27 个字段对外，且有三方写者：EngineAPI 创建、CEF 命令队列、脚本直写；读取则散落在 CEF、Acoustics、Geometry、Display。
  • 04
    协议面已经有 133 个字段、35 个结构体。相机命令、拾取回执、帧就绪/消费事件、截图 promise 都是现成的“封装后 API 雏形”，不需要从零设计。
  • 05
    图像槽不是 DAG 私有。主线程 VulkanBackend 为 UI 图层在同一 ImageStorage 里分配槽，并读 consumed_receipt 做回压——所以 ImageDevice 应定位为“帧交换结构”，收敛可见面（receipt + metadata），而不是整体隐藏。
